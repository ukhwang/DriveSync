# 본선 라이브 시연 대본

화면 구성의 원본은 [design/screens.md](../design/screens.md)의 **7개 상태**입니다. 이 문서는 운영자 조작과 발표 포인트만 담습니다.

## A. 웹 시연 프로토타입 (서류·백업 시연)

`cd prototype && npm ci && npm run dev` → `http://localhost:5173`, 브라우저 전체 화면(1920×1080).

| # | 조작 | 발표 포인트 |
|---|---|---|
| 01 | 화면 그대로 설명 → `주행 브리핑 준비 완료` | 상단 바 **CarUxRestrictions 해제 + P단**. 내비 ETA 18분 → 중거리 1분 브리핑으로 자동 매칭. 카드마다 `[내 기록]`/`[AI 추론]` |
| 02 | `일시정지` → `계속 재생` → `중지` → `음성 메모 (1-Tap)` | 주행 제한 = 목적지·ETA·재생 제어·메모 버튼만. 운전자에게 묻지 않는 일방향 브리핑. 탭 한 번으로 멈춤(운전자 우선권) |
| 03 | 8초 기다리면 `저장됨` | 단발성 메모(최대 2분, 설정으로 변경 가능, 말이 끝나면 자동 저장), 확인음만. **주행 중에는 전사문·AI 분석을 보여주지 않음** |
| 04 | 화살표로 회전 → 가운데 카드 탭 → `내용 수정` | 도착 후 제한 해제 + P단 확인 시 공개. 기획서의 핵심 3줄·우려사항·예상 질문·이동 중 메모. AI 추론 줄을 고치면 `[내 기록]`이 됨. 여기서는 아무것도 발송하지 않음 |
| 05 | 메일 `검토 시작` → 본문 한 줄 수정 → `이 항목 승인` → 일정도 승인 → `승인된 2건 실행` | Human-in-the-Loop: 항목별 Draft → Review → Approved. 승인 0건이면 실행 불가 |
| 06 | `다시 승인 후 재시도` → `연결 복구 (시뮬레이션)` | 지하주차장에서 일정 등록 실패를 실패로 표시. 다시 승인해야 재시도, 같은 실행 키로 1회만 반영 |
| 07 | 탭 전환 | 차량 신호를 믿을 수 없으면 안전 잠금, 세션은 암호화 보존 |

## B. 차량 앱 + 실제 발송 (본선 라이브)

Pleos Connect 에뮬레이터의 Kotlin 앱과 실제 서버로 같은 흐름을 보여줍니다(아래 #는 [screens.md](../design/screens.md)의 14화면).

| 장면 | 운영자 조작 (시뮬레이터 패널) | 발표 포인트 |
|---|---|---|
| 01 | 정차 · P → 방문 선택 | 목적지 매칭, ETA 구간별 브리핑 (#1–#2) |
| 02–03 | 주행 시작 → 메모 버튼 → ETA 9분 → 4분 | 최소 화면, 단발성 메모, ETA 급변 시 핵심 문장만 (#3–#5) |
| 07 | 신호 끊김 → 신호 복구 | Fail-Safe 후 자동 복귀 (#6) |
| 04 | 도착 0분 → 정차 · P | 치트시트 공개 (#7) |
| 05 | 디브리핑 입력 → 검토 → 승인 → 실행 | **실제 수신함 도착을 화면 밖에서 확인** (#8–#11) |
| 06 | 노트북 Wi-Fi 끄고 실행 → 재시도 예약 → Wi-Fi 켜고 다시 승인 | Failed → Retry → Executed, 중복 발송 없음 (#12–#13) |
| — | 승인 대기 중 주행 시작 → 정차 | 주행 시작 시 승인 보류 (#14) |
